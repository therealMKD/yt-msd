# yt-msd build toolchain for the Cython -> .exe release build
# Install with:  python -m pip install -r requirements-build.txt
#
# Non-pip requirement (already installed on this machine):
#   Visual Studio Build Tools 2022  ->  MSVC 14.44 (cl.exe 19.44) + Windows SDK 10.0.26100
#   Verified working with Cython 3.3.0 on Python 3.14 (both .pyd extension builds and
#   standalone "cython --embed" executables), using either toolset:
#     VS 2026 BuildTools -> MSVC 14.50.35717 (cl 19.50)  <- auto-selected by setuptools
#     VS 2022 BuildTools -> MSVC 14.44.35207 (cl 19.44)
#   No Developer Command Prompt is required: setuptools auto-detects MSVC + the Windows SDK
#   (10.0.26100.0) from a plain PowerShell prompt. If you ever want to force a toolset, call:
#     call "C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Auxiliary\Build\vcvars64.bat"
#
# Run the tools as modules so you do not depend on the Scripts folder being on PATH:
#   python -m cython --version
#   python -m PyInstaller --version
#
# Source-name requirement (verified): Cython rejects "yt-msd-gui" because it is not a valid
# module name, and it will not read a .pyw at all. The Cython source therefore lives at
#   GUI Source Code\yt_msd_gui.pyx
# which is the text of GUI Source Code\yt-msd-gui.pyw with only a header of Cython directives on
# top, so the compiled build behaves exactly like the script and the .pyw stays the master copy.
# build_gui_cython.py (repo root) keeps the two in step:
#   python build_gui_cython.py sync     rewrite the .pyx from the .pyw
#   python build_gui_cython.py verify   prove the .pyx body is byte-identical to the .pyw
#   python build_gui_cython.py c        write build_dir_cython\yt_msd_gui.c  (add --embed for a main())
#   python build_gui_cython.py check    transpile into a temp folder and report warnings only
# Verified: Cython 3.3.0 transpiles the current 9900-line GUI source with no errors or warnings.
#
# build_gui_exe.py (repo root) finishes the job - it drives build_gui_cython.py, MSVC and PyInstaller:
#   python build_gui_exe.py pyd       .pyx -> .c -> build_dir_cython\yt_msd_gui.cp314-win_amd64.pyd
#   python build_gui_exe.py launcher  write the launcher + build_dir_cython\yt-msd-gui.spec
#   python build_gui_exe.py exe       build GUI Source Code\yt-msd-gui\  (one folder: yt-msd-gui.exe + _internal\)
#   python build_gui_exe.py installer pack that folder into GUI Source Code\yt-msd-setup.exe (needs Inno Setup)
#   python build_gui_exe.py all       pyd + launcher + exe + installer
# The build is a folder rather than one big exe on purpose: a one-file exe unpacks its ~550 MB into a temporary
# "_MEI" folder before the window appears (about 4 seconds here) and deletes it again after the window closes,
# which keeps a hidden parent process alive for seconds after the window is gone and delays the next start. A
# one-folder exe starts from the files beside it (window in ~1.2 seconds) and exits with the window. The single
# file an end user downloads is still one file: yt-msd-setup.exe, which unpacks that folder into
# %LOCALAPPDATA%\Programs\yt-msd and adds a Start menu shortcut.
# One spec builds one program from the same compiled .pyd. The GUI is windowed and so has no console of its
# own, while the renamer is an interactive console program (banner, colours, input() prompts), so the single
# exe decides which half to be at startup: with no flag it runs the GUI, with "--renamer" or "-r" it runs the
# renamer. Started from a terminal it prints in that terminal; started by double-click, or by the GUI (which
# is windowed too, and CREATE_NEW_CONSOLE only works for a program that is a console program to begin with),
# it calls AllocConsole() and puts the new console's handles on the standard descriptors, which gives the
# renamer a window of its own to print and prompt in. The GUI reaches it by running a second copy of itself
# as "yt-msd-gui.exe --renamer <folder>", which is the built form of "yt-msd-gui.pyw --renamer <folder>".
# The exe carries everything the GUI needs at run time except yt-dlp: the compiled GUI itself, PySide6,
# mutagen, Pillow, watchdog, python-vlc, libvlc.dll + libvlccore.dll + the VLC plugins folder (taken from
# the VLC install found through the registry, i.e. the same one python-vlc would use), ffmpeg.exe +
# ffprobe.exe (found on PATH, then in the winget/chocolatey folders; set YTMSD_FFMPEG_DIR to force one),
# and icon-256x256.ico - all of them in the _internal folder beside the exe, so the GUI can use the icon for the
# title bar, the taskbar button and the tray, which is also the icon embedded in the .exe itself. The exe finds
# that folder through sys._MEIPASS, which for a one-folder build is the _internal folder next to it.
# The launcher exists because PyInstaller cannot read imports out of a compiled .pyd: it restates the .pyw's
# own import lines so nothing is missing from the bundle, and runs the .pyw's entry block inside the compiled
# module, which keeps sys.modules[__name__] intact (what "cython --embed" would not do).
