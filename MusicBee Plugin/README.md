# MusicBee plugin

The plugin itself doesn't actually do anything besides open yt-msd, and create a button in the MusicBee tools menu. This plugin allows yt-msd to be opened from the musicbee tools menu directly. (In a smaller-windowed version) On close, as well as every 30 seconds while the program is open, the plugin forces a rescan of all tracked folders inside Musicbee, so downloaded songs are found immediately.

## Install

Download `mb_YtMsd.dll` from [releases](https://github.com/therealMKD/yt-msd/releases/latest), then put it into `%APPDATA%\MusicBee\Plugins` OR go into the musicbee plugins menu (Preferences > Plugins > Add Plugin) and select the dll file. Either way, a copy of the dll will get placed in the plugins folder. Once the plugin is there, you will have to enable it (You might have to restart musicbee for it to show up) and then restart musicbee for the yt-msd option to show up in the tools menu.

With no `mb_YtMsd.ini` file, the program looks for yt-msd in the default installation directory: `C:\Users\[your username]\%AppData%\Local\yt-msd\`. It looks for a file named `yt-msd-gui.exe` and runs it. If your yt-msd location is different, you will have to download the ini file, and place that in the SAME directory as your plugin (Your MusicBee plugins folder). You will also have to edit it to point to the correct file, according to the [settings](#use).

## Settings

`mb_YtMsd.ini` sits next to `mb_YtMsd.dll`. By default, every single line is commented out. To make a line take effect, remove the asterisk from that line. The following argument lines exist in the ini file:

```ini
exe=C:\Users\you\yt-msd\GUI Source Code\yt-msd-gui\yt-msd-gui.exe
dir=C:\Users\you\yt-msd\GUI Source Code
folder=C:\Users\you\Music
maxfiles=3000
interval=30
```

* `exe` - the program the menu entry opens.
* `dir` - a folder to search for the program in; repeat the line for more folders. Used when there is no `exe=`, or when the `exe=` there points at a file that is gone. Will attempt to locate a file named `yt-msd-gui.exe`, `yt-msd.exe`, `yt-msd-gui.pyw`, or `yt-msd.pyw` up to 1 layer deep.
* `folder` - a folder to scan for new files; repeat the line for more folders. With no `folder=` lines the plugin falls back to MusicBee's download folder and your Music folder.
* `maxfiles` - safety limit on how many files one scan will look at.
* `interval` - seconds between scans while yt-msd is open. `0` means only scan once yt-msd has been closed. This is set to 30 by default without an ini present, or when this line is commented out.

For most cases, the only thing you will need to touch is the exe path, but you should probably also change the dir path, just to be safe. The exe path does not have to be an exe, it can be a .pyw file if you have the python version. To find the correct path to put here, navigate to the program's location, right click on the .exe or .pyw file, and select "Copy As Path". This will give you the exact path of the folder, to replace the placeholder path. To get the correct dir path, just remove the last two sections of the exe's path (Reference the placeholder). Remember, you also MUST remove the asterisks on those lines, otherwise the plugin will ignore them! Changes will not take effect until Musicbee has been restarted.

If the plugin is unable to find the exe's location for whatever reason, it will generate a file in the same folder named `mb_YtMsd.log`, which details the places searched, and the problem encountered. If the log file names a place that the exe is located in, doublecheck the ini file (if it exists), as well as the name of the exe file.

## Build

**The rest of this file is generated by AI, and is kept as future reference for my local agent**

Only needed after the C# sources change. It writes into `MusicBee Plugin\release\`:

```
python "MusicBee Plugin\build_mb_plugin.py"              compile into MusicBee Plugin\release\
python "MusicBee Plugin\build_mb_plugin.py" --install    compile and copy into MusicBee too
python "MusicBee Plugin\build_mb_plugin.py" --clean      delete the release folder
```

No .NET SDK is needed. The script compiles with a C# compiler that is already on the
machine - Roslyn from Visual Studio / Build Tools, or the .NET Framework's own
`csc.exe`. The plugin is AnyCPU (MusicBee is 32-bit) and targets .NET Framework 4.x,
which is what MusicBee runs on.

`--install` copies `mb_YtMsd.dll` into `%APPDATA%\MusicBee\Plugins` and writes a
settings file there using this machine's real paths. An existing settings file is
left alone - delete it first if you want it replaced. `release\mb_YtMsd.ini` stays
the path-free template either way. `C:\Program Files (x86)\MusicBee\Plugins` also
works but needs an elevated prompt:

```
python "MusicBee Plugin\build_mb_plugin.py" --install --plugin-dir "C:\Program Files (x86)\MusicBee\Plugins"
```

If neither folder is picked up, use **Options > Plugins > Add** in MusicBee and pick
`MusicBee Plugin\release\mb_YtMsd.dll`.

## Entry points MusicBee requires

When MusicBee loads a plugin assembly it checks for three methods on
`MusicBeePlugin.Plugin`:

```
PluginInfo Initialise(IntPtr apiInterfacePtr)
void Close(PluginCloseReason reason)
void ReceiveNotification(string sourceFileUrl, NotificationType type)
```

`ReceiveNotification` is required even for a plugin that only asks for the startup
notification - without it MusicBee refuses the plugin with *"Unable to initialise
plugin: mb_YtMsd.dll. Dll entry point: ReceiveNotification was not found"*. It is a
no-op here because yt-msd does its work in its own process.
